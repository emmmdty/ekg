# 周进展模板

> 用法：复制为 `docs/reports/YYYY-MM-DD_周报.md`，逐项替换 `<>` 占位，删掉本行以上的说明。
> 升降如实；ssh / 工具失败写进第 3 节，不写成结论；负结果是交付内容，不是待修的 bug。
>
> 写作口吻：面向导师，不假定读者知道仓库、任务编号或实验缩写。用平实、克制的研究汇报语言，先说明研究问题、实际工作和当前结果；内部代号、提交号、哈希和脚本路径只在确有必要时用自然语言解释，不作为正文主语。避免“完成闭环”“有效推进”“显著提升”等空话，也不要写模板化总结。结果好坏如实写，卡点直接说明。
