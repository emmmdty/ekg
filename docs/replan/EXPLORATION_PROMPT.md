# 探索任务：事件图谱 / 事理图谱在 LLM 时代的研究地形勘测

> 用途：为一篇硕士学位论文重定选题与章节骨架收集证据。
> 本文件是**给探索者（人或 agent）的完整提示词**，可整份投喂，也可按 Block 拆给并行子代理。
> 产出是**证据报告**，不是方案建议 —— 方案在证据回来之后另行决定。

## 0. 背景（探索者必读）

**课题**：硕士学位论文，主题「事件图谱（或事理图谱，二选一）的构建及其应用」，
应用场景定位为**风险监测**。课题来源于一个「大宗商品价格风险监测」的实际项目，
希望保留一定相关性，但**大宗商品本身不是硬约束**（该领域公开数据集匮乏，已确认不能照做，
需要从中抽取一个可研究的子方向）。

**硬约束**：

| 约束 | 内容 |
|---|---|
| 数据 | **只用公开数据集，不做任何人工标注**。数据必须可下载、可复现。 |
| 算力 | **单卡 NVIDIA RTX 5090**，约 27GB 可用显存（另有约 5GB 被长期占用）。无多卡、无集群。 |
| 结构 | 3–4 章，**每章有独立的方法贡献**，且能在公开数据集上与已发表方法（经典 + 近两年）**同口径比较**。 |
| 标尺 | 每章需在**公开可比的主指标**上**超过多个（不是一个）**已发表方法。 |
| 闭环 | 全篇需形成闭环、自洽、逻辑一致（章与章之间有承接关系，不是三个独立小论文装订）。 |
| 新颖性 | 允许「在他人已有工作上做优化改进」，不要求颠覆性原创，但必须能讲清 delta。 |

**职业落点**：作者希望论文的技术栈偏 **LLM / Agent 工程**方向（也接受图谱/抽取算法方向，
如果课题自然走到那里）。这是**倾向**，不是筛选条件 —— 请如实报告地形，不要为迎合它而裁剪结论。

**已有资产（用于评估「重构 vs 重开」，不构成方向约束）**：
一个约 1 万行的 Python 项目，围绕 **MAVEN 系列**（MAVEN-ERE / MAVEN-Arg / MAVEN-FACT）构建，
含判别式关系抽取、事件共指、事实性检测、后继事件预测（SeDGPL 基座）、conformal 校准等模块。
现状是四章里只有一章（事实性检测）超过了公开方法。

## 1. 探索原则（**违反任何一条，报告作废**）

### 1.1 先找真问题，再看竞争密度

**⛔ 不得按「对手弱不弱、好不好超越」来推荐方向。** 这是选题的错误第一原则。

每个候选方向请**分两栏独立报告**，不要合并成一个推荐分：

- **栏 A｜问题价值**：这个方向有什么尚未解决的真问题？谁在 survey / limitation 段落里明确点名了它？
  LLM 出现之后它是变得更重要还是被绕过去了？
- **栏 B｜竞争密度**：这个 benchmark / 任务上，2024–2026 有多少篇已发表方法在打？分数是密集还是稀疏？

两栏都要，但**不要用栏 B 去否决栏 A**。作者要判断的是"值不值得做"，"能不能打赢"是随后的工程问题。

### 1.2 所有数字必须回一手来源

报告里出现的**任何**指标数字，必须同时给出：

1. **出处**：论文标题 + arXiv ID 或 ACL Anthology 编号 + **具体表号**（如 "Table 3"）
2. **split**：这个数字是在 train / dev(valid) / test 哪个集合上的
3. **评测脚本**：官方脚本？自实现？论文是否声明？**未声明就写「未声明」**
4. **指标定义**：micro / macro、是否含 negative class、F1 的聚合方式

> ⚠️ 这条是从惨痛教训来的：本项目曾**四次**因为「内部口径 vs 官方口径」混用而判错方向
> —— 两轮实验白跑、一次把"未达标"误判为"达标"、一次把优化方向搞反。
> **拿两个不同 split / 不同评测器的数相减是无效操作。** 凡不能确认三条轴对齐的，明确标注「不可比」。

### 1.3 必须核查 test 集可得性

很多事件类 benchmark 的 test 标签不公开，需走评测服务器，而**服务器可能已经关闭**。
（本项目在 MAVEN-ERE 的 CodaLab 上吃过亏：竞赛页写 "Ends: Never"，实际提交已被管理员禁用，
官方 test 分永远拿不到，只能退而在 valid 上自跑对手代码作对照。）

对每个候选数据集，**必须明确回答**：

- test 标签是否公开下载？
- 若不公开：评测通道（CodaLab / EvalAI / 官网）**当前是否还在收提交**？（请实际访问确认，不要只看页面声明）
- 近两年的论文**实际报的是哪个 split**？有没有论文明说"因为 test 不公开所以用 valid 当 test"？
- 如果主流做法是在 valid 上报数，请**列出至少两篇这么做的论文**作为先例证据。

### 1.4 区分「有代码」和「能跑」

GitHub 项目必须注明：

- 最后一次 commit 时间、star 数、是否 archived
- 是否含**完整训练脚本**（很多 repo 只放推理或只放 demo）
- 显存需求 / 论文里报的训练硬件（**关键**：单卡 27GB 能不能跑）
- issues 里是否有人报告**复现成功或失败**
- 依赖是否还能装（老 repo 常锁死在已下架的库版本）

### 1.5 找不到就说找不到

数据集拿不到（许可证 / 链接失效 / 需要 LDC 会员）、论文查不到原文、数字核不出来
—— **如实写「未取得」并说明原因**。**不要用相似的东西冒充，不要凭印象补数字。**
一条「未能核实」的诚实记录，比一个错的数字有价值得多。

## 2. 需要回答的问题

### Block 1 — 领域地形与真实卡点

1. **术语地图**：`event knowledge graph` / `eventuality graph` / `event graph` / `事理图谱(event logic graph)` /
   `script knowledge` / `narrative graph` / `event-centric KG` —— 这些在文献里分别指什么？
   哪些是同一个东西的不同叫法？中文「事理图谱」在英文文献里对应哪一支？
   **作者需要在「事件图谱」和「事理图谱」之间二选一，请给出选择依据。**

2. **2024–2026 的 survey / position paper** 怎么描述这个领域的开放问题？
   请找出明确点名 open problem / limitation / future work 的段落并**引原文**。
   建议检索方向：event knowledge graph survey、event extraction survey、
   event causality identification survey、script learning、narrative understanding、
   temporal knowledge graph、structured knowledge for LLM。

3. **LLM 冲击了什么**：
   - 哪些子任务在 GPT-4 / Llama 级模型出现后**基本被拉平**（即 zero/few-shot 已接近或超过监督 SOTA）？
   - 哪些子任务 LLM **依然做不好**？请给出**具体的实测证据**（论文 + 表号 + 数字 + split），
     不要只引"LLM 在结构化抽取上仍有挑战"这类空话。
   - 有没有论文**系统评测过** LLM 在事件抽取/事件关系/事件共指上的表现？结论是什么？

4. **新任务形态**：LLM 时代有没有围绕事件图谱长出**新的任务定义**？例如：
   - 事件图谱作为 LLM 的**外部记忆 / agent memory**
   - **GraphRAG** 及其事件化变体
   - 事件图谱用于**长文档/多文档理解**、时间线构建
   - 事件图谱作为**推理链的可验证支架**
   - 用 LLM **自动构建**图谱（含多智能体建图）
   这些新形态有没有配套的公开 benchmark 和已发表方法？（**有 benchmark 才谈得上超越**）

5. **这个领域在 2026 年还活着吗**：2025–2026 顶会（ACL/EMNLP/NAACL/COLING/LREC/AAAI/IJCAI/WWW/SIGIR/CIKM）
   上事件图谱相关论文的数量趋势是升是降？如果在降，是被什么吸收了？

### Block 2 — 有活跃竞争的公开数据集（**核心块**）

产出一张**总表**，每行一个数据集，列：

| 数据集 | 年份 | 语言 | 任务 | 规模 | test 标签可得性 | 通道是否活着 | 2024–26 跟进方法数 | 当前最好数字（出处+表号+split） | 单卡可跑？ |
|---|---|---|---|---|---|---|---|---|---|

**必须覆盖的候选**（请核实、修正、并**大量补充你找到的其他数据集**）：

- **事件检测/抽取**：MAVEN、ACE05（en/zh/ar）、ERE、TAC-KBP、RAMS、WikiEvents、DocEE、GLEN、MAVEN-Arg
- **事件关系**：MAVEN-ERE、EventStoryLine (ESC)、Causal-TimeBank、MATRES、TimeBank-Dense、TORQUE、CRAB
- **事件共指**：ECB+、GVC、FCC、MEANTIME、CD²CR
- **多语言/跨语言**：MEE、MINION、MEANTIME、ACE05 多语言部分、以及任何你找到的新的多语言事件数据集
- **中文**：DuEE、DuEE-fin、FewFC、CCKS 系列、CMNEE、以及新的中文事件数据集
- **事件预测/脚本**：MCNC、事件时间线、后继事件预测相关
- **事实性/可信度**：MAVEN-FACT、FactBank、UW、Unified Factuality
- **风险/危机/社会事件**：SPEED 系列、ACLED、GDELT、ICEWS、EM-DAT、灾害/疫情事件抽取数据集

**特别标注**：
- **2024 年以后发布**，且**已有 ≥2 篇他人方法论文跟进**的数据集 → 这是"新数据集 + 有对手"的理想区间，请重点挖。
- 有**公开 leaderboard 且仍在更新**的。
- 哪些数据集事实上已经**饱和**（近两年分数原地踏步或只有小数点后的提升）。

### Block 3 — LLM 时代的方法范式与可复现实现

1. **LLM-based 信息抽取的当前做法**：instruction tuning（IEPile / InstructUIE / KnowCoder / ADELIE 等）、
   code-style prompting、schema-guided、retrieval-augmented、agent/multi-agent 分解。
   各自在事件类 benchmark 上的**实测数字**（出处+表号+split）。

2. **关键事实核查**：在**事件关系抽取**（因果/时序/子事件）和**事件共指**上，
   LLM 方法**是否真的**超过了微调的小模型（RoBERTa/DeBERTa 级）？
   请给出正反两方面的证据。这条直接决定作者的技术骨干选型。

3. **多智能体 / agent 建图**：除已知的 CGEL（Koupaee et al., ACL 2025, arXiv 2506.06910）之外，
   还有谁在做「用多个 LLM 协作构建事件/因果图」？他们用什么数据、什么指标、和谁比？

4. **单卡可行性**：哪些方法的开源实现能在 **27GB 单卡**上训练/微调？
   7B LoRA、14B QLoRA 的实际显存占用与训练时长参考。
   哪些方法**必须**多卡或调用闭源 API（→ 对我们是不可比或不可复现的对手，需要标出来）。

5. **评测基础设施**：这些 benchmark 的官方评测脚本在哪里？有没有社区统一的评测框架？

### Block 4 — 两个候选切口的可行性（**只做可行性核查，不做推荐**）

#### 切口 α：跨语言 / 多语言事件图谱

- 有哪些**公开的**跨语言或多语言事件数据集？规模、语言覆盖、任务类型、test 可得性。
- 跨语言事件**对齐/共指**（同一起真实事件在不同语言报道中被识别为同一节点）有没有公开数据集？
  有没有已发表方法？**如果这块数据稀缺，请明确说，不要为了让切口成立而美化。**
- 主流 setting 是什么：zero-shot 跨语言迁移？多语言联合训练？翻译-对齐？
- 近两年有哪些方法、什么 baseline、分数分布如何。
- **这个方向的真问题是什么**（栏 A），不只是"有数据可以做"。

#### 切口 β：供应链中断 / 大宗商品 / 经济风险事件

- 有没有**公开的**供应链中断、大宗商品、经济风险相关的事件抽取或事件图谱数据集？
- 如果没有专门数据集：通用事件数据集（MAVEN/ACE/ACLED/GDELT 等）里的哪些**事件类型子集**
  可以构成一个风险相关的评测子集？有没有论文这么做过（**有先例才不算自造评测**）？
- 有没有「事件 → 风险/价格/中断」的**公开下游任务与 benchmark**？（注意：价格预测类任务
  信噪比极低，本项目已在股票预测上失败过一次，请特别核实是否存在**可验证的事件层面**下游任务，
  例如事件链补全、中断传播路径预测、时间线构建、预警检测。）
- 工业界/开源社区有没有相关的项目或数据（如供应链风险监测系统、EM-DAT 灾害库等）。

