# 哈工大航天学院控制工程专硕：章节结构与实质工作量审查

日期：2026-10-29。作者已明确：哈尔滨工业大学航天学院，电子信息（控制工程），专业硕士。
本页是研究设计建议，不是论文正文，也不是学位评定分委员会的审核结论。

## 1. 结构建议及其条件

**建议采用两个扎实的方法研究章＋一个事件图谱构建与工程验证章，不为数量增加第三方法章。**
这种结构符合目前查到的本校写作指南所引用的专题研究类论文框架。成立的条件是：两项
方法贡献确实有不同的问题与证据，工程章确实评价系统实际输入下的有效性和代价。
“结构有依据”与“现有A/B足以支撑结构”是两件事；后者当前不成立，B的既有版本已否决。

三方法章只有在第三项具有单独的问题、必要技术差异、公共对照和完整结果时才更强。
把同一个网络的三个组件拆章，或把普通图纠错包装成另一方法，反而增加重复和论证缺口。
工程类专硕仍需工程背景与验证；改成三方法章不自动免除这些内容。

## 3. 参照论文提供了什么结构证据

重新核读作者提供的四篇论文目录和章节边界，具体页数唯一记在
[R1 §25.147](../../results/PHASE_R1.md)。其中李娜是两递进方法＋系统；余羿辰和朱若彬
也包含两项核心方法研究与图谱/系统构建。李佳蔚则是表示、融合、主题分析、应用的
较宽链条，不能机械等同三个现代神经网络方法章。

前者的第二方法承接第一方法不足，说明**独立贡献不要求完全独立代码**。但必须有
新增问题、明确机制差异，并用上一方法和强替代作对照。只在上一章加一个模块、
只换一项loss或只增加一组消融，不自动构成完整的新研究章。

参照论文的篇幅只能证明结构先例，不能证明其方法都很新、其成绩都合法可比，或
我们用同样页数就能通过评审。既有四篇质量限制继续认R1 §25.121，不重新美化。

## 4. 逐章要有多少实质内容

下表是**未来内容容量的规划估计**，不是已完成字数，也不是把尚未成立的B预留篇幅
就算解决。总体按本校正文要求组织，不用重复背景、代码清单或大幅截图填充。

| 部分 | 拟承担的内容 | 建议正文量（含图表的规划口径） |
|---|---|---|
| 第1章 绪论 | 工程需求、同任务研究现状、问题边界与研究链条 | 4,000—5,000字 |
| 第2章 基础与统一任务定义 | 必要模型背景、原生标签/候选、数据协议；避免每章重写 | 3,000—4,000字 |
| 第3章 方法研究一 | 残余问题；数学/计算定义；训练推理；多语料主结果；归因与边界 | 8,000—10,000字 |
| 第4章 方法研究二 | 独立新问题；与前章的关系；方法及目标；独立主比较；机制与失败分析 | 8,000—10,000字 |
| 第5章 图谱构建与工程验证 | 完整输入链、部署输入质量、系统对照、错误传播、资源与功能验证 | 6,000—8,000字 |
| 结论 | 成果、适用范围和遗留问题 | 1,500—2,000字 |

合计约3.05万—3.9万字。方法章可按约16—22页、工程章约12—16页检查内容容量；
**页数只是排版前估计，随公式/图表变化，不是学校定额或强行填满的指标**。

每个方法章至少需要以下完整证据内容：

1. **问题**：强基线的具体不足，以及为何现有最接近方法尚未解决；不能只写某模块缺失。
2. **方法**：输入信号、网络计算、监督来源、训练和部署差别、复杂度；不能只有框图。
3. **主比较**：目标三个、至少两个独立公开语料；同列协议一致的强对手，上一方法参与递进比较。
4. **归因**：核心干预的移除/替代、最强简单解释、有效负控；不会因结论不利而撤掉。
5. **边界**：P/R交换、句内/跨句、监督稀疏和成本，解释失败而非只选成功案例。

这些内容能支撑篇幅，前提是实际有结果和不同的论断。同一主表换排版、同一实验
在两章重复计数、工程适配故障数量、阅读论文数量均不算新增研究工作量。

## 5. 应用/工程章必须补强什么

上一版“给定mentions→预测边→画图→重复关系F1”不够充实。事件ID与边可逆地序列化
后再算同一个F1，本质还是前两章的关系结果，不能当作新的应用有效性证据。

工程章建议回答：**在固定自动事件输入和实际资源约束下，关系改进能否转化为更好的
可追溯事件图谱，代价和失败边界是什么？** 形成以下验证包，不新增人工数据：

| 工程问题 | 对照/测量 | 与方法章的区别 |
|---|---|---|
| 给定事件条件下的收益能否落到实际输入 | 同一固定事件检测器下的base/A/最终第二方法/组合；公开标注的span＋关系三元组P/R/F1 | 实际事件检出、漏检和误检参与最终结果，金标mention只作明确的上界条件 |
| 哪类上游错误导致收益消失 | 对固定预测mention作边端点可恢复性与错误来源分解；不从test定分层规则 | 识别模块质量到构建结果的传递边界；不是把两次关系分数相加 |
| 系统能否保真构图 | 节点span、候选ID、边方向/类型与证据原文可回查；输入输出守恒与固定功能用例 | 支撑工程正确性；不称此项是新的算法创新 |
| 是否具有实用代价 | 固定环境的峰值显存、单文档延迟、吞吐与图规模分层 | 实测部署代价；不能只报理论O符号或单个小样本 |
| 是否只依赖有利组件 | 固定上游下的模块替换，合法输入质量条件下的收益/退化 | 支撑系统结论，不恢复旧已撤销的全factorial |

[SEAG原文§4.2](https://aclanthology.org/2023.findings-acl.283.pdf)提供事件三元组匹配
评价的公开先例，但其§4.1会按标注事件对构造连续句段；不能直接继承后宣称原始
全文自动部署。当前未定位其作者运行仓库，不能把SEAG列为已可跑系统对手。
另已定位[Seq2Rel作者仓库](https://github.com/JohnGiorgi/seq2rel/tree/3f15c67d3b1e64033565192bc4a84b9de2d1c345)，
有真实reader/model/metric和训练配置，但发布的是CopyNet/AllenNLP实现，不能冒称
就是SEAG表中的T5适配。工程对照可优先固定同一检测器＋分类器、同一检测器＋ERGO、
同一检测器＋最终方法；生成式对照需另核语料序列化、重复mention定位和真实旧栈。
既有本地`EventDetector`组件接收候选对象，尚未验收新语料的无标签候选生成；有类名
不等于真实端到端系统可用。正式工程合同须冻结**不依赖gold事件/关系的输入打包**、
匹配规则、固定检测器及同实例适配，不能到最后用金标窗口弥补接口缺口。

该章可以是“构建与工程验证”，不必强加新的事件预测任务。旧E3因上游身份不同
仍只保留历史证据，不能直接充作新A/B的下游效果。新闻/百科实验也不直接证明航天
业务已部署；专业关联应落在经确认的智能信息处理工程问题及其验证。
