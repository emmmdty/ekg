# 综合裁决：当前可信结论与逐章推进方式

日期：2026-10-29。范围：科研方案审查；无新模型代码、训练、日历或最终评测。
本页是执行代理的综合判断，不是独立专家评审，也不是方法有效性的实验证明。

## 1. 直接决定

**采用逐章推进：先闭合共同数据/对照与构建端点，再完成第一项方法的开发证据，
随后依据其剩余错误确定第二项改进，最后完成构建与工程验证。**

组织方案推荐“两方法研究章＋一构建与工程验证章”，暂不增加第三条方法研究线。
现在冻结共同问题、接口、公共对照和各章须交付的证据；具体网络随证据分章冻结。
不能宣称两项方法已经成立，也不能把第三研究章的一切准备推到前两章完成之后。
本页的“第一/第二/第三”均指研究章顺序，非旧规范中的章号。

理由是研究依赖：第二方法应回答第一方法仍未解决的问题，工程验证应检验方法收益
能否穿过事件检出误差保留下来。三章共享同一语料身份、事件定位及关系输出，需要
先证明可接通；三套网络同时锁死会把未经验证的假说当成需求。

学校依据来自[章节审查](CHAPTER_STRUCTURE_REVIEW.md)所列哈工大/工程专硕文件。
所核文件要求研究深度、工作量和应用或验证，没有查到必须三个方法章的条款；此为
已核文件范围内的判断，不能代替学院/年级的全部实施要求或个人学位审核。

## 2. 当前研究结果究竟是什么

数字与计数唯一引用[R1 §25.146—148](../../results/PHASE_R1.md)及
[既有关系实验](../../results/PHASE_A.md)，本页不重抄分数。

| 结论 | 证据及可相信的范围 | 尚不能据此相信什么 |
|---|---|---|
| 公开ECI任务仍可研究，基准较旧不等于选错 | ICGR等近期论文仍评价ESC/MAVEN；DiffusECI跨ESC/CTB/MECI。任务/版本有直接先例 | 数据能下载不能证明我们的方法一定有效，也不能证明全部输入协议已适配 |
| 不能用所有任务都高于某一分数判断论文价值 | 原表中句内、跨句、方向、存在和包含事件检出的分数明显不同；细项认R1 | 原表低分不能为我们低于同协议强对照辩护，也不能据裸分判定是否落后 |
| 已有最新训练是有边界的真实负结果 | PHASE_A末节有原机重载、官方核分、完整预测、配对区间与误差交换 | 开发集、单seed且选过checkpoint，不是最终泛化确认；区间跨零也不证明两方法等效 |
| 第一候选A有明确计算和可证伪对照 | 两腿联合Q、边缘乘积、交互残差D的差别已定义；CRFIE提供直接高阶强替代 | 新颖性充分、三语料有效、实际显存/时间和条件power尚未证明 |
| 第二候选B可按小改进重新审查 | OOF/图推理已知；显式预测错误监督的编辑门与ICGR retained-edge support的作用位置、目标不同 | 未发现逐项相同不证明原创；门控不同也不等于能改好关系或足以成章 |
| 图谱节点并不要求另外有实体节点 | 实例事件提及本身可作节点，以span/原文证据定位；预测关系作边 | 给定gold事件提及的关系实验不等于任意原文全自动构图或跨文档事件融合 |
| 第三章有工程验证路径，但尚未闭合运行 | 找到MAVEN官方DMBERT真实训练/无类型标签候选推理代码；现有图结构和关系资产可复用 | 无标签候选分类不等于从任意原文找span；新语料/同实例对齐和公共端点仍待验收 |

可信度按具体论断区分：来源、代码和本地结构观察可复查；章节路线是有条件的设计
判断；新增方法收益目前没有实证。不给它们统一“可信百分比”，也不把文档完成度
冒充方法完成度。此前“B用了已知组件，所以不构成方法”的推断过强，本页纠正。

## 3. 两个方法章如何定，而不是把问题留给作者

### 第一研究章：先裁交互残差A

问题：文本条件下，两条相关关系的联合交互是否能提供超出边缘信息、普通联合读出
和辅助监督的判别价值。保留现有强文本分类路径，只审一项明确的交互读出改进。
架构/损失的已有公式认[设计§2](DESIGN_AND_REVIEW.md)，不重新发明图推理框架。

主对手来源优先为已有ERGO有效实现；跨语料对照从ERGO、PPAT、DiffusECI实际可适配
代码中准入，按语料能力与保真度逐列登记，不预报三者全可运行。直接机制对手为
CRFIE高阶关系因子/MFVI族：仅使用其真实实现作透明适配，未完成适配前不报复现。
消融保留full-Q、product、aux-only、有效target归属负控；二类语料增加等效标量容量
控制。必要性、张量容量、监督权重、完整候选覆盖与合法选模须先写成无歧义合同。

科学去留：若同协议强替代解释全部收益，则停止这份具体D方案；结果如实归档，
不以改seed、扩大backbone或挑语料保留它。尚未准入模型实现/训练，这一状态不变。
当前继续它的理由是能区分“联合依赖”与“额外监督/容量”两个解释，且已在活动
R122范围内有可审计算；不是因为预期它必涨分或只是开发方便。

### 第二研究章：保留有针对性的预测错误修正B，分开问题和具体实现

问题位先确定为：在第一方法或共同强预测器仍有误报/漏检时，能否按真实预测错误
选择性修改关系，降低纠错同时破坏正确关系的代价。既有错误交换支持需要兼顾
误报和检出，尚不能证明“结构传播错误”是唯一根因。

候选计算保留[设计§3](DESIGN_AND_REVIEW.md)：冻结F的预测＋共享事件的pair邻域→
一次消息聚合→显式错误监督编辑门g→残差修正logits。训练编辑标签只来自外层train
内部的OOF预测与train gold，推理不使用正确性标签。OOF本身归已知训练协议。
这里允许在既有框架上增加一项有依据的编辑机制，**不要求新算法家族**。

最近邻实质差别：ICGR §3.5式14从干净/去噪latent产生支持门，增强保留边置信度，
再作图消息传播；候选B的u是初始分类是否出错，门用于最终分类logits的有符号修正。
ICGR已有MLP门/噪声门控制，普通门不是我们的贡献。其全文并未证明这份B严格等价，
也没有证明B有益；Stacked Graphical Models已覆盖OOF邻居概率的基本框架。

因此B恢复为**有条件待审候选**，没有恢复第二方法已达标或任何训练授权。其最小
辨别实验必须包括：同OOF/同容量/同监督的无结构编辑器；普通图refiner；去掉显式
错误监督的编辑门；真实OOF与合成噪声训练；合法校准控制；有效结构归属负控。
应记录修对错误和改坏正确的交换。若差别只来自普通二阶段分类或额外监督，就限定
结论或停止此精确版本，不能把“用了图”充作创新。

顺序上，在第一方法完成冻结开发比较后，用已有开发证据明确第二方法的目标错误
和最小改动，再冻结其网络/消融。第一方法自己的最终评测仍须事前签发；最终测试
不用于选第二方法。第一方法若未成立，先解决该章，不用另开两条未验证方法填章。
第二方法可以递进依赖第一方法，不要求完全独立代码；自身需有完整问题、直接对照
与可归因收益。一个有用模块可以支撑研究，单个模块也不自动保证整章工作量。

## 4. 第三个研究章：现在必须确定哪些，哪些后做

建议章名为“实例级事件图谱构建与工程验证”。核心问题：关系改进在预测事件节点
输入下是否仍有效，哪些损失来自节点检出、哪些来自关系判别，资源代价是否可接受。
这与方法章给定事件提及时的关系识别是两个评测条件。

构建链：公开文本/预声明候选→固定事件检测器→预测事件span节点→关系预测→
带证据来源的事件边图。节点的gold类型/论元/簇和关系均不进入预测。默认保持mention
节点，不另开身份消解创新；只有预测输出才能合并节点。事件节点可独立存在，实体
论元若无预测或task-given来源，不用gold补齐。关系方向只在原生有向条件报告。
候选对象对模型只暴露公开span/文本及不含正负来源标记的opaque ID，不暴露gold事件簇
或只对正例存在的event_id；标注与评分映射另存，预测节点由检测输出重新生成。

**新增一手代码核查**：MAVEN官方repo
`THU-KEG/MAVEN-dataset@71151f6da53bc9df9d6c5718dc81a2e1489651bf`
有DMBERT的model、trainer、train/dev reader及`MAVENInferProcessor`。后者读取提供的
candidate span，以无类型标签的对象前向；不是span proposal模型。根LICENSE为MIT，
部分复用文件保留Apache头；README指定旧transformers版本，未安装/运行或检验checkpoint。
这给“公开候选内的事件检测＋关系构建”提供源码路径，未证明任意原文检测已就绪。

分清两个合法层级，并在第一方法实现前裁定：

- **提供候选的构建验证**：若公共任务提供无标签candidate，节点由固定检测器分类
  得到；可做预测节点与gold节点条件的配对比较，标题/结论明确候选范围。
- **任意原文构建**：另需公开、可复用的无gold span proposal及覆盖明确的标注/评分。
  未闭合前不作为已确定的主张，不用gold事件对生成窗口冒充部署输入。

主系统对照按同一检测器＋公开文本分类器、同一检测器＋ERGO、同一检测器＋A、
同一检测器＋最终第二方法设置；独立可定义时增加B-only/A+B。每项保持同文档、
同候选和同评分。SEAG §4.3已有DMBERT＋BERT/Longformer/ERGO的流水线先例，
§4.2按事件与关系三元组匹配计分；其§4.1使用gold事件对确定连续句段，不能直接
借其成绩宣称我们的全文条件达标。生成式对手作为扩展，代码未闭合前不承诺准入。

端点预声明：事件检出P/R/F1；span对＋原生关系类型/方向严格匹配的三元组P/R/F1；
同一关系方法在gold/predicted事件条件的错误传播；推理时间/峰值显存及输出可追溯。
三元组指标沿用公认形式，但**新增候选、分段或数据适配后不冒称已有官方同协议榜单**。
要先冻结匹配、重复span、漏检计FN、误检相关边计FP及未知关系mask，保留检测为NONE
和关系为NONE的区别；对未标注边不自作NONE。图外观与自造拓扑指标只作辅助。

本地又发现具体混淆源：`RelationPipelineConfig`默认`consistency="greedy"`，
并非纯序列化；`GreedyConsistencySolver`可删因果环、加时间闭包。构建主比较须明确
原始预测与后处理身份，优先identity忠实导出；若评价固定后处理，应对所有方法
成对应用并同时报告前后结果。不得在工程章悄悄改输出后仍归因于关系新方法。

现在要闭合的是输入来源、标注覆盖、ID/span对齐、评分和可运行对照来源；实际模型
前向、系统成本与完整功能验收在获准实现后完成。若上述输入/公共端点仍不成立，
在第一方法大规模执行前收窄构建范围；不等两个方法全部完成才发现无合法系统任务。
这章仍是有条件的工程方案，不能拿它抵消第二项方法贡献尚未成立的缺口。

## 5. 数据与新颖性决策

保留MAVEN-ERE为现有主锚，ESC v0.9和CTB为跨语料候选；MECI-English为备用。
不因发布时间换数据。CTB不能支撑跨句推理论断；MECI有未标注pair和同文章chunk跨split
问题，不能临时补NONE或用原split宣称未见文章泛化。至少两个独立语料必须形成有效
方法主证据，目标三个；第三列退出/替换须在方法评分前裁定，不能因成绩差删列。

新补检索到FrECI（ACL2026）：官方页面说明它增加责任目标、框架、来源和模态等标签，
属于扩展任务。这只支持“不是直接替换当前ECI主列”的判断，本轮没有审全文、代码
或其完整分数，不将其作为已核可运行对手。追近期机制与保持可比较基准可以同时做。

## 6. 三种顺序的综合取舍与冻结边界

| 顺序 | 研究上的后果 | 裁决 |
|---|---|---|
| 现在同时锁三项方法 | 尚无第三个具体问题，会把同一问题分拆或预设未知结论 | 不采用 |
| 前两项全部结束再研究第三章输入/评分 | 可能最后才发现节点、关系和评估不在同一人口 | 不采用 |
| 共同端点先审，方法逐章冻结与完成，工程实现后置 | 可以保留同一任务闭环，用第一章残余证据决定递进贡献 | 采用 |

现在固定：单一任务范围；公开数据准入原则；final-valid边界；共同ID/span/候选/输出
合同；每章强对照/主指标/失败条件；第三章输入层级与评分可行性。
分章固定：具体改动、容量、训练目标、endpoint和消融；在该章首评分前完成。
后置：模型实测和工程实现；实际结果不能现在填写。

所有后续接续仍认唯一[实验主表§4](../../EXPERIMENT_PLAN.md)的C41-A-R/T087。
当前紧接的是A的具体增量裁决及公共多语料/构建输入合同闭合，不要求作者选方向。
需要真实模型运行才能解决的缺口明确标明，不用进一步写文档声称已解决。
文件继续放本目录，代码复用现仓库，未来产物新namespace隔离，不另开工程目录/队列。

证据身份见[integrated_sources.json](integrated_sources.json)。自审只能减少前置错误，
不能保证以后不发生假设失败；冻结的是有效性与变更规则，不是必须成功的结论。
