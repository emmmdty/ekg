# 新方向独立项目的组织裁决

2026-10-30。作者后续明确由DeepSeek实施；最新要求与验收见
[建设委托](DEEPSEEK_FOUNDATION_HANDOFF.md)：短课题名、功能模块、统一三端环境及数据机制。
本文是组织与迁移方案，不是创建仓库或迁移服务器数据的执行记录。
对应[总审查](READINESS_AUDIT.md)与[R1证据](../../results/PHASE_R1.md)。

## 1. 建议

**建议新方向最终使用独立的轻量研究项目，拟名`cdecr`。**旧`ekg`项目保留其
代码、历史实验和封存结果；本次研究材料仍在旧仓库完成审查/交接，不在此时开第二
队列、分支、worktree或模型任务。目录/仓库的建立属于后续明确的实施动作。

| 组织方式 | 对当前情况的影响 | 裁决 |
|---|---|---|
| 在旧`src/ekg`继续追加 | 根SPEC仍要求身份/关系/事实性与下游预测；默认测试、schema和阶段规范绑定旧路线 | 不建议作为新研究主工程 |
| 在旧仓库内建可独立配置的子项目 | 能隔离Python包和输出，但根交接/规范仍会持续进入会话，须维护两套任务入口 | 可作审查过渡目录，不作为最终首选 |
| 独立轻量项目 | 一份任务spec、一套数据/评价合同、一个活动队列；公共实现和原数据按身份复用 | 推荐；无需重建整套框架或复制旧研究历史 |

依据包括：旧SPEC的FR-001/002/008要求多任务/消费者评价；`EventNode`要求event_type
且以单doc记录为中心，新主任务却是跨文档提及分区；旧pyproject仅打包`src/ekg`且
默认测试为旧任务。它们并非不可改，而是大量修改仍不能增加新CDCR研究贡献。
独立项目的理由是研究范围和规范一致，不是借新目录绕过有效性或资源限制。

## 2. 新项目最小范围

建议同级目录`/home/tjk/myProjects/masterProjects/cdecr/`，核心只有公开数据接口、
候选检索、pair精判、簇归并和统一评价。可以直接采用/适配现有公共库；不重新开发
通用训练平台、全图数据库、事件检测器或关系抽取系统。

建议入口为`README.md`、精简一致的`AGENTS.md/CLAUDE.md`、`docs/SPEC.md`、
`docs/PROTOCOL.md`、`docs/BASELINES.md`和三章方法设计。代码命名按功能，如
`cdecr/data`、`retrieval`、`pairwise`、`clustering`、`evaluation`，不按章号命名。
配置、结果、外部来源补丁与许可分别可查；只有一条活动实验队列。

正式spec只约束：gold-mention CDCR、三主语料/已发表划分、全人口合法分区、共同
主辅指标、GVC0处理、主表/原分的比较边界、公共对照、train/dev选模及输出追溯。
不携带旧MAVEN的阶段名、阈值、身份根、失败机制和下游MRR目标作为新任务门槛。

## 3. 迁移复用与禁止混用

- 复用研究框架、九表原分、指标规范和本次总审查；每项保留旧repo commit/path/hash。
  外部数字继续只在新项目的唯一结果权威中维护，导航链接指向权威，不复制多份漂移。
- 复用三语料原始文件及上游身份，原件不改。按同一manifest在三端
  建立物理副本并校验哈希，不用指回旧项目的软链接、硬链接或外部数据路径作运行依赖。
- 官方代码按发布身份复用、保留许可和透明补丁；公共代码不是自有贡献。许可未说明
  的代码不擅自声明为MIT；不同许可证的源码不合并成一个无来源的新包。
- 只挑适用的ID校验、追溯和CPU工具，不拷贝旧流水线、旧权重或旧成绩充当新任务结果。
  文献原分、公开baseline适配和自有结果始终区分。
- 保留本地不跑GPU、远端资源授权、单seed、train/dev与最终评价隔离、只读封存、如实
  报告和跨机搬运先授权等有效性/资源边界。新项目不自动取得机器或多seed权限。
